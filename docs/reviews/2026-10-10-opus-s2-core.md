# Review: S2 A1 `s2-core` (`spike/s2-wgpu`, `5f34f6b`)

Reviewer: opus subagent, read-only, 2026-10-10. "Verified" = an experiment showed it
(`/data/scratch/s2/review/exp/src/bin/{keys,emu,more}.rs`); "inferred" = from reading.
`cargo test -p s2-core` passed; 25 consecutive runs, 0 failures.

## Verdict

**Merge with fixes.** Must-fix before Track B builds on it: B1, B2, B3, B4, B5, B7, B8 (code or contract), the
missing tests, and the contract-note gaps. B6 and the lower-severity items can follow.

## Must fix

- **B1 — a large paste deadlocks the emulator thread and `Emu::drop` then hangs** (`emu.rs` `send`/`paste`, reader
  back-pressure loop, `pty.rs` `write_all`). Verified. The emulator thread does a blocking `write_all` while it is the
  only thread that drains `queued`. Paste ≥ 160 KiB into `cat`: the child echoes, the reader queues past 256 KiB and
  stops reading, the child blocks on output and stops reading input, `write_all` never returns. 32 and 100 KiB pass;
  160 KiB, 300 KiB, 1 MiB, 4 MiB hang; `drop(emu)` did not return in 10 s. Inferred: same for keys typed at a child
  that never reads stdin. Fix: non-blocking/chunked writes interleaved with draining output, or a writer thread.
- **B2 — reader thread leaks and spins after shutdown under flood** (back-pressure loop). Verified: 300×100 grid,
  `cat /dev/zero | tr '\0' a`, drop after ~100 ms → 40 of 40 left an `s2-pty-read` thread waking every 200 µs. The
  loop never checks whether the emulator is gone; the thread is never joined.
- **B3 — a resize attributes pending keys to a frame without their echo** (`run`: `resized.then(now_ns)`). Verified:
  `stty -echo; sleep 1000`, key id 1, wait, `Resize(90,30)` → frame has `keys=[1]`, empty row 0. Fix: frames with no
  PTY output must not satisfy attribution.
- **B4 — Ctrl + punctuation sends nothing in legacy mode** (`keys.rs` `physical`). Verified: `Ctrl+[`, `Ctrl+\`,
  `Ctrl+]`, `Ctrl+/`, `Ctrl+_`, `Ctrl+@` encode to `""` (only letters, digits, space are mapped). Correct with kitty
  flags on.
- **B5 — control-character `text` gives a wrong sequence** (`keys.rs` `set_utf8`). Verified: `Char('c')` + ctrl +
  `text: Some("\x03")` → `ESC [ 3 ; 5 u` instead of `\x03`. The core should strip C0 text.
- **B7 — wake-ups before `set_waker` are lost** (`run` initial publish, reader exit wake). Verified: child `true`,
  waker set 300 ms after start → exited, 0 wake calls, one frame pending. Fix in the core (fire on `set_waker` when a
  frame is pending or the child exited) or document "poll once after `set_waker`".
- **B8 — frames taken but never logged lose their keys; `taken` grows without bound** (`latency.rs` `frame_taken` /
  `frame`). Inferred, high confidence: front-end takes F1 (keys [1]), takes F2 before rendering, presents only F2 →
  key 1 gets no frame line. The lost keys are the ones that missed a frame, so p95/p99 are biased low. Fix:
  `log.frame(seq)` folds in every taken-but-unlogged seq ≤ `seq`, or the contract states one `log.frame` per `take`.

## Should fix later

- **B6** — under kitty "disambiguate", Shift+a (text "A") → `ESC[97;2u`, "!" → `ESC[33;2u`: `consumed_mods` is always
  empty and the unshifted codepoint is `to_lowercase(c)`. Verified output; that it is wrong is the reviewer's reading
  of the kitty spec. Matters for fish 4, neovim, helix.
- Keys, pastes and resizes in a batch are applied before bytes read earlier: input right after `CSI ?1h` /
  `CSI ?2004h` is encoded under the old mode (one-batch window). Inferred.
- `at_wide_tail` is dropped: with the cursor on the second half of a wide char, `Cursor.col` points at the spacer
  cell. Verified.
- `unseen_keys` grows while the child prints nothing, then all land on the next frame. Inferred.
- `exited` is set and the waker fired before the emulator processed the last `Bytes`: a front-end closing on
  `exited()` can miss the final frame. Inferred.
- No cwd is set; `CommandBuilder` defaults to `$HOME`, so a relative `--cmd` resolves against home. Inferred.
- Only the direct child is killed on drop. Inferred.
- The waker runs with the waker mutex held: a waker calling `set_waker` self-deadlocks. Inferred.

## Checked and correct (verified)

Dirty rows: 40 seeded runs × 400 random ops (scroll, regions, IL/DL, SU/SD, RI, ED/EL, ICH/DCH, alt screen, wide
chars, hyperlinks, SGR) with frames taken at random so the slot merges — a consumer copying only dirty rows never
went stale and the final grid matched a fresh emulator. (Resize was not in the random mix.) Cursor-only moves dirty
old and new row; OSC 4 gives a full redraw; a wide char at the last column wraps; paste strips ESC/control bytes; no
duplicated or reordered keys.

## Contract / A1 deviations not in the contract notes

- `Frame::t_output_ns` is `now_ns()` for the initial and resize frames, and the last chunk's read time for a
  multi-chunk batch; the contract says "when the PTY bytes that produced this frame were read".
- The old rule "first frame whose `t_output_ns` ≥ its `t_write_ns`" is still in the latency-log section of the
  overview and contradicts the A1 note.
- Public API Track B must call but the notes omit: `bench::Sampler::start(Log)` (stop by drop),
  `Log::frames_logged()`, `keys::Encoder`, `keys::paste_bytes`, the `Mods` fields.
- Heads-up for A2: "wheel → viewport" has no `InputMsg`; the terminal is private to the emulator thread, so
  scrolling needs a contract addition.

## Tests that would pass with the feature broken

- `emu_frame_after_output`: `taken <= 100` also holds for a plain queue (latest-wins untested); `dirty_rows[0]`
  passes if every row is always dirty.
- Nothing tests `FrameSlot::publish` carrying over keys and dirty rows.
- `key_reaches_pty_and_is_attributed_to_a_frame`: no negative case (so B3 passes).
- `resize_changes_frame_and_pty_size`: the PTY size is never checked.
- `exit_is_reported`: does not check the waker.
- `keys_no_repeat_after_focus_loss`: tests the helper only, not the thread.
- `keys_encode_letter_and_ctrl`: no punctuation or kitty cases.
- Golden pair: no frame with `t_output_ns < t_write_ns`, so an `analyze.py` that does not clamp negatives passes.
- `pty_echo_roundtrip` would hang rather than fail (blocking `read` inside the timeout loop).

## Measurement validity

- **Flood runs do not measure echo-visible latency** (verified): any output read after the write began counts as the
  echo. With `stty -echo; yes flood` a key was attributed ~1.1 ms later to a frame with no echo. Under flood,
  key→present and the `--photon` square mean "next frame after the key". Quiet runs are sound. State this in results.
- Stage split is unreliable for carried-over keys (frame line carries the newer `t_output_ns`); key→present is not
  affected. Inferred.
- Survivorship bias from B8; wrong attribution from B3.
- Full-grid clone per publish (verified, release): 0.11 ms at 80×24, 0.52 ms at 200×60, 1.4 ms at 300×100.
- The sampler runs `nvidia-smi` every 500 ms inside the measured process and flushes the log under the mutex that
  `log.key`/`log.frame` take. Inferred.
- Reader back-pressure polling (up to 200 µs) shows up as write→output time under flood. Inferred.
- The log is flushed only by `flush()` or the sampler; a killed app loses the last buffer. Inferred.
