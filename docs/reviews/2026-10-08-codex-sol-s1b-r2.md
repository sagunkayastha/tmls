# Review: S1b round 2 (`spike/s1b-r2`, `56a63d0`)

## Verdict

The **S1 corpus result is supported within its stated comparison**: the final artifact has 3,901 distinct `(stream, split)` AlignedCarry cases, all identical, across 24 streams. There are 3,354 distinct `(stream, effective_split)` snapshots because non-boundary splits align backward. The final taxonomy has zero AlignedCarry residuals. See `/data/scratch/s1/results/2026-10-08-s1b-r2-run5/summary.md:151`, `taxonomy.md:12-24`, and `cases.jsonl`; the runner writes one case for every selected split and strategy (`spikes/s1/src/main.rs:213-228`). `skip.txt` excludes only the incomplete Claude recording (`spikes/s1/corpus/skip.txt:1`; loader at `main.rs:139-156`). This is a sampled corpus claim, not equality for every byte offset or every future stream.

The S1 comparison is unchanged. `grid::normalize` still collapses only plain default blanks (`spikes/s1/src/grid.rs:216-236`); `grid::diff` still compares cells and the same `TermState` fields (`grid.rs:238-290`); history is still Formatter Plain, `unwrap(false)`, first `scrollback_rows` lines, right-trimmed (`spikes/s1/src/experiment.rs:143-166`). Case identity remains `diff.is_identical() && history_equal` (`experiment.rs:209-225`). `wrap_flags_equal` is assigned after restore but never enters that expression (`experiment.rs:210,245`). The taxonomy class is assigned only after a case is non-identical (`experiment.rs:249-267`); its priority cannot turn a mismatch into a pass. The Naive/Aligned/AlignedUnwrap totals also remain 1,840/2,792/2,782 against round 1 (`docs/spikes/S1b-results.md:9-14`). The unchanged comparison is narrower than full terminal identity: history styles and links, underline variants, protection, saved-cursor slots, and several other fields are outside it (`run5/summary.md:6`).

## Must fix

- **Before freezing §5.2 attach/reconnect, resolve or explicitly accept the three resized handoff failures.** The final simulation has 480/480 plain and 477/480 resized cases, with `wrap_pending` splits 679, 681, and 688 each losing `"m"` at viewport cell (20,1) (`/data/scratch/s1/results/2026-10-08-s1b-r2-handoff-verified/cases.jsonl:852,854,856`; handoff comparison at `spikes/s1/src/handoff.rs:193-203`). Their exact root cause has not been isolated. The row-flag fallback is a plausible carry/reflow contributor, but the artifact does not distinguish a carry bug from a Formatter limitation. No upstream Draft C is justified yet. The documents correctly keep production attach provisional (`docs/spikes/S1b-residuals.md:13-17`; `docs/PLAN.md:131-135`).

## Should fix

- **Soft-wrap preservation is incomplete relative to the plan.** The code reads history and viewport flags through `grid_ref(...).row()?.is_wrapped()/is_wrap_continuation()` (`spikes/s1/src/grid.rs:82-99`). It sends the *whole* Formatter output through `with_unwrap(true)`, then falls back to the *whole* wrapped format if a probe's flags differ (`spikes/s1/src/carry.rs:173-192`; `spikes/s1/src/snap.rs:62-66`). It does not emit only flagged wrapped rows. The fallback restores S1 equality for the 14 run4 regressions, and the existing pending-wrap replay remains at `carry.rs:258-270`; the seeded `wrap_pending` S1 test asserts identity (`experiment.rs:723-733`). Yet 28 final snapshots still have unequal flags: 10 `wrap_pending`, 14 `less`/`less_prompt`, and 4 `utf8_wide_combining` (`docs/spikes/S1b-results.md:18`; independently counted from `run5/cases.jsonl`). The 300-column reflow test covers one simple line (`carry.rs:499-517`), not those 28 cases. Investigate these flags alongside the three resize failures before describing soft-wrap carry as complete.
- **Document or parameterize the fixed 2,000-byte probe scrollback.** `snapshot_full` and its row-deficit probe restore into temporary terminals with literal `2000` (`spikes/s1/src/carry.rs:175,208-215`), while a handoff can carry a different scrollback setting (`spikes/s1/src/handoff.rs:18-20,62-76`). The measured runs all pass `--scrollback 2000` (`run5/summary.md:3-4`), so this does not undermine their result, but the current API has an unstated configuration assumption.
- **Add direct alt-mode edge tests before relying on mode-specific semantics generally.** The primary prefix is captured immediately *before* the entry unit is fed (`spikes/s1/src/carry.rs:49-52,65-77`), and replay uses `AltEntry.mode` rather than always 1049 (`carry.rs:183-190`). Thus the 47-mode repair is credible: final cases 1394/1395/1400 are identical with `alt_mode_at_split=47`, `snap_faithful=true`, and no post-tail mismatch (`run5/cases.jsonl:9728,9732,9736`). However, the focused residual test checks one 47 exit and final S1 identity only (`experiment.rs:712-721`); it does not assert 1047 clear-on-exit, 1049's saved cursor separately from explicit `ESC 7`, or nested/repeated entries. The tracker retains one `AltEntry` and clears it only when an exit contains that recorded mode (`carry.rs:65-82`). These untested paths should be measured before claiming all 47/1047/1049 transitions are equivalent to uninterrupted parsing.

## Minor

- The ECH overlay follows the specified selection rule: per viewport row, it groups empty-text, non-wide cells with equal background, skipping the column after a wide lead; it emits a run only if the background is set or later content exists on the row (`spikes/s1/src/carry.rs:285-305`). The run1 regression (3,104/3,901, mostly history/text loss) shows why the spacer guard matters; run2 recovered to 3,870/3,901 (`/data/scratch/s1/results/2026-10-08-s1b-r2-run1/summary.md:151`, `run2/summary.md:151`). ECH itself does not move the cursor, but the preceding CUP does; the saved-cursor handling and final CUP/pen tail follow it (`carry.rs:240-275`). It cannot directly rewrite history rows. The corpus proves the tested final history *text* agrees; history cell styles, links, and erased identity remain unmeasured.
- ECH chooses cells using text, wide-lead adjacency, and background, without checking other cell attributes or hyperlinks (`carry.rs:285-305`). A targeted styled or linked empty-cell test would establish whether erasure can remove non-background state outside the current corpus. The final 3,901 cases show no such S1 mismatch.
- The plan requested a round-2 run1 matrix table. The results document reports final run5 and narrates run1, but does not give its 3,104/3,901 total or 765 scrollback-class failures in a table (`docs/spikes/S1b-results.md:7-27`; `run1/taxonomy.md:12-24`). This is a reporting gap, not a changed gate.

## Unmeasured

The client reply result is **zero attempts in these 960 simulated cases**, not a generic reply-disable mechanism. Both snapshot and tail are passed through a finite query-unit filter (`spikes/s1/src/handoff.rs:89-103,124-152`), and the final handoff artifact records zero (`/data/scratch/s1/results/2026-10-08-s1b-r2-handoff-verified/summary.md:5-30`; `cases.jsonl`). The worker's offset and resize epoch are exercised in-process (`handoff.rs:172-192`); atomic snapshot/subscription, replay retention under races, network delivery, emulator-lock behavior, and phase-aware suppression of bell/title/clipboard effects are not (`docs/PLAN.md:126-135`). PLAN §5.1's single reply authority and §5.2's side-effect contract therefore remain unproven in production.

## Merge recommendation

**Merge as a measured Linux spike with the S1 corpus gate closed**, while retaining §5.2 attach/reconnect as provisional. PLAN §6's stated S1b equality alternative is satisfied by 3,901/3,901 (`docs/PLAN.md:184`); the three resize failures do not create an S1 corpus residual, and none of the old 73 classes needs an upstream issue filed. Do not label resize-epoch handoff or generic soft-wrap carry complete until the three failures and 28 flag discrepancies are resolved or explicitly accepted with evidence. No test was rerun for this read-only review; the counts above were independently checked from saved artifacts.
