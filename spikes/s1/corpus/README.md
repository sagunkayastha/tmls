# S1 terminal-output corpus

Raw bytes real programs wrote to their PTY, for replaying into the S1 parser/grid spike.

## Method

The original S1 `record.sh` started a private tmux server (`tmux -L s1rec`, never the default server) with
`new-session -d -x 120 -y 40 -s rec "env TERM=xterm-256color COLORTERM=truecolor TMPDIR=/data/scratch/s1 sh -c 'sleep 1; <cmd>'"`,
then immediately `pipe-pane -o 'cat >> /data/scratch/s1/corpus/<name>.bin'`. The 1 s `sleep` guarantees
pipe-pane is attached before the program paints. Input is driven with `send-keys`; the session is
ended by the program itself or `kill-session`/`kill-server` on `-L s1rec` (nested test also `-L s1b`).
The `.bin` is therefore the exact byte stream the program wrote to the pane's PTY (tmux's own
re-rendering to a client is NOT included). `TERM` is forced with `env` because tmux otherwise sets
`TERM=tmux-256color`/`screen` inside panes.

Each `<name>.meta.json`: `{"cmd","cols":120,"rows":40,"bytes","sha256"}`.
Full set lives in `/data/scratch/s1/corpus/`; recordings < 200 KB are copied here (all of them currently).

The current `record.sh` is v2: it defaults to four **new names**, uses a unique private tmux socket and a new status file, and refuses to overwrite any existing `.bin` or `.meta.json`. It starts an interactive `bash --norc --noprofile` prompt for each prompt-first stream, types `ls --color=always` and `echo $RANDOM`, runs the program, then types `echo after program` after quitting. The prior seven recordings remain byte-for-byte unchanged. `skip.txt` excludes the partial `claude.bin` from corpus loading.

## Failures

- **claude**: the fresh TUI stops at the "Quick safety check: do you trust this folder" confirmation
  (`Enter to confirm`), so no prompt UI appears (a retry with cwd=/home/sgkayast hit the same dialog for that
  folder). Per plan this is a skip, not a failure of the run. A 1333-byte partial `claude.bin`/`claude.meta.json`
  (trust dialog only) may exist in this directory and in `/data/scratch/s1/corpus/` from the attempt; ignore it
  (pane dump in `/data/scratch/s1/corpus/claude.pane.txt`). `record.sh` now always runs claude in the repo dir.
  To record it: accept trust once by hand in `~/Others/tmls-rs` (`cd ~/Others/tmls-rs && claude`, choose
  "Yes, I trust this folder", exit), then `spikes/s1/corpus/record.sh claude`.
- **nested** (degraded, kept as measured): the recorded `$c` put single-quoted inner `send-keys` arguments inside
  `start`'s outer `sh -c '…'`, so the inner quotes ended the outer string and the inner commands were mangled; the
  follow-up `send-keys` to the inner panes failed silently (`2>/dev/null || true`). The 4137-byte stream is
  mostly blank panes + status bars. `record.sh` is fixed (the outer pane runs only the inner tmux client; the
  inner server is driven from the script by pane id and every inner command must succeed; a dry run into a scratch
  dir gave ~15 KB with the ls/git output). **Not re-recorded**: S1 results use the 4137-byte stream; re-recording
  is the S1b follow-up.
- **cargo**: with only `touch main.rs` on the shared `target/` the stream was 386 bytes, so the script builds
  into its own `CARGO_TARGET_DIR=/data/scratch/s1/cargo-target` (first run = full build incl. deps). A second run
  into the same dir is again tiny; for a full build use `S1_CARGO_TARGET=/data/scratch/s1/cargo-target-2`.

## Record another v2 corpus

```
cd /path/to/tmls-rs
spikes/s1/corpus/record.sh            # four v2 names, only if they do not exist
spikes/s1/corpus/record.sh vim_prompt # one new name, only if it does not exist
```
The script refuses existing recording paths; use distinct names for further captures. Results are printed at the end; each invocation has a new `/data/scratch/s1/corpus/status-v2.*.tsv` file.
